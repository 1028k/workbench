### 1) 2026-10-31 · B站 搜索框「能打字、按回车没反应」
- 复现：B站 场景左侧网页，点顶栏搜索框 → 输入 → 回车/点放大镜，页面纹丝不动。
- 根因（探针实测）：B站 顶栏搜索**没有 form action / target**，提交时 JS 自己
  `window.open('//search.bilibili.com/all?keyword=…&from_source=web_search…')`。
  而 embed 的 `<webview>` **默认不开 allowpopups**（2026-10-19 为了不往系统浏览器弹 Edge 才关的）
  ⇒ 内核把这次弹窗直接掐掉，页面上什么都不发生。
  视频卡片能点，是因为 `startBiliTrack` 里的 LINKFIX 早把 `a[target=_blank]` 就地化了 ⇒ 才出现"视频能点、搜索不能"。
- 修法：`renderers.js` 新增 `installSameTabPopups(wv, meta)`，往 guest 注一段脚本，**只**把
  「目标是 `search.bilibili.com` 或 URL 带 `keyword=`」的 `window.open` / `form[target=_blank]` 改成 `location.href`；
  其它 `window.open` 一律原样（B站自己会用 window.open 开 `leader-election/iframe.html`、
  `CrossOriginLocalStorage`，那些拿去导航会把面板跳飞）。
  幂等（`window.__dshNoPopup`）、失败静默、每次 `dom-ready` / `did-finish-load` 重装；只对 `meta.scenario === 'bilibili'` 生效
  （别的面板要同样行为，在场景 json 写 `"sameTabPopups": true`）。

### 2) 本机验证手法（B站 这种"嵌网页"的问题，别再靠肉眼猜）
- `外壳\node_modules\electron\dist\electron.exe` 起一个临时脚本：`BrowserWindow({show:false, webPreferences:{webviewTag:true}})`
  → 页面里塞 `<webview src="https://www.bilibili.com">`（与外壳同款 guest）
  → `guest.sendInputEvent()` 真打字 + 回车（可信输入，比 JS 合成事件靠谱）
  → `guest.executeJavaScript()` 注入 / 读 `location.href`。
- 2026-10-31 实测结论：不注入 = 停在首页（弹窗被掐）；注入 `installSameTabPopups` 那段后 =
  跳到 `https://search.bilibili.com/all?keyword=nba&…`，`document.title` 变成「nba-哔哩哔哩_bilibili」，结果页正常。
- ⚠ Electron 会在 mojo 建命名管道时 FATAL（`platform_channel.cc:108 拒绝访问`）—— 那是执行沙箱挡的，不是代码问题；
  换个允许起进程的环境/策略再跑。

### 3) 模拟键鼠在 PowerShell 里不可用（踩过，别再试）
- `SetCursorPos` 返回 False、`mouse_event` / `SendInput` 全部无效果（连点外壳自己的标签都不动）；
  但 `CopyFromScreen` 截桌面**能用**。
- 所以"截图看现状"可以，"模拟点/打字来复现"不行；要复现就走第 2 条的 Electron 探针。
