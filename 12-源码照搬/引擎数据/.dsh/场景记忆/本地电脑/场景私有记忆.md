## 五、坑与决策

- 2026-10-31｜pc-scan.mjs 从来没存在过：renderers.js 里 pc-toplarge / pc-junk 的空态写着「让 AI 跑 scripts\pc-scan.mjs」，但 外壳\scripts 下只有会话/面板类脚本，data 里也没有扫描结果 ⇒ 这两块面板永远停在空态。补建后按 renderer 的 PC_DATA 契约产出 scannedAt / tookSec / minGb / items / byDrive / junk / junkTotalGb（少一个字段面板就空态或解析异常）；数据落 `外壳\data`，路径来自 preload 的 paths.dataDir（= 外壳\data，不是 引擎数据\.dsh）。
  - 挑榜规则：子目录 ≥ 父目录 75% 就沿单链往下钻，报最具体那一层且不再进这一枝 ⇒ 榜单条目互不包含，体积不会重复计。
  - 时间预算必须分阶段：体检单独 120~180s（Windows 更新缓存一项就要 ~90s），剩下按盘平分。最初 240s 一次全给 C 盘，D 盘直接被跳过，Windows 也只量出 14.5GB 假数（真实 34.4GB）。
  - 坑：browserCache 返回的是 {total,first,n}，进榜单前必须换成 {path,bytes}；字段名对不上会静默记成 0（Edge 缓存曾这样丢掉 0.82GB）。
  - 本机实况：只有 C:（132.9G / 剩 8.0G）和 D:（341.8G / 剩 95.2G），E:、F: 不存在 ⇒ 面板那两张卡显示「未就绪」是正常的。D 盘大户：剑网3 Pakv4 106.7G、WeGame downloading 48.7G、mhxy 28.1G。
  - 后台跑要 `*> 日志文件`：后台 job 拿不到流式输出，没日志就分不清是卡住还是没输出（踩过一次，20 分钟以为挂死）。
  - 体检现状（2026-10-31）：合计 11.67GB，其中 Windows 更新缓存 9.81GB、Edge 缓存 0.82GB、回收站 0.57GB。
- 2026-10-31｜「重新扫描」按钮：渲染层只有 file.read/write/stat，没有列目录/执行能力 ⇒ 按钮只能请主进程起子进程（`kun:pc:scan`），扫的还是同一个 pc-scan.mjs。**main.js / preload.js 改动都要重启一次 GUI**；renderers.js / styles.css 是热更（⟳ 或重启都行）。按钮在前一块「磁盘大户排行」和「可清理体检」的面板头上，空态里也有（那正是最想扫的时候）。
  - 起进程：先 `ELECTRON_RUN_AS_NODE=1` + `process.execPath`（实测 Electron 43 内置 node v24，跑 .mjs 没问题），900ms 内非 0 退出就退回 PATH 上的 `node`；detached + unref ⇒ GUI 关了也跑完。同一时间只放一个扫描，连点不会并发扫盘。
  - 坑：PowerShell 里 `& electron.exe 脚本.mjs` 对 GUI 程序**不等**，紧跟着 Remove-Item 会在子进程读文件之前把文件删掉 ⇒ 假报 `MODULE_NOT_FOUND`（踩了一次）；要测就用 `Start-Process -Wait`。
  - check-gui.mjs 现在 1 个 FAIL（main.js require 的 `./updater.js` 不存在），是历史遗留、被 try/catch 包着不影响启动，不是这次改出来的。
- 2026-10-31｜「重新扫描好像没用」的真因（用户 20:19 报）：扫描其实起得来、也跑完了（日志 20:14:57 → JSON 20:19:22）。问题在**反馈**：
  - ① 面板每 15~20 秒 `wrap.innerHTML=''` 整块重画 ⇒ 按钮上"扫描中…"的**局部状态 15 秒后就被抹掉**，看起来像没点。
  - ② 扫描 4~5 分钟没有任何进度 ⇒ 用户默认"没反应"。
  - 修法：进度落 `data\pc-cleanup-scan.state.json`（脚本写 running/phase/drive/pct/files/dirs，每 ~0.7s 一次），按钮/面板**每次都从文件推状态**（不存局部变量），显示「扫描中 42%」，title 里带"已看 N 个文件 · 已 X 分 Y 秒"。轮询定时器必须绑 `btn.isConnected`，否则面板重画后老按钮的 interval 会一直跑（泄漏）。
- 2026-10-31｜「清理」按钮（用户点名）：**渲染层删不了文件**，也不该让面板自己删 —— 清理必须由场景 AI 按 pc-cleanup 技能走（先列清单等点头 → 直接删 → 记台账）。按钮只负责"传话"：在 AI 面板的 webview 里 `POST /api/session/prompt`（信封同流程画布「▶ 开始」，见 flowSceneSession），sessionId 从场景 json 读，**不能问 webview 当前显示哪条**（切过会话会发错地方）。发不出去就 toast 报原因，不静默失败。
- 2026-10-31｜第一次真清理（回收站 + Windows 更新缓存）踩到的坑：
  - 回收站：`Clear-RecycleBin` **不需要管理员**，0.57GB 秒清；它会对不存在的 E:/F: 报 "找不到路径"，但 C: 已经清了，别被那句错误吓到。
  - C:\Windows 下删除**必须管理员**。两次提权（PowerShell 脚本、cmd 批处理）都在几十秒内被终止（退出码 0xC000013A），只删掉 5.06GB（9.81→4.75GB）。像是安全软件/系统保护在拦，**别再硬试**；正路是「磁盘清理 / 存储设置→临时文件」这类签名工具，或让用户自己在管理员 PowerShell 里跑。
  - ★坑：提权脚本里**先停服务再长删除**最危险 —— 进程一被杀，服务就停在停止状态且没人恢复（这次 BITS 停了一小时）。要么不停服务，要么在脚本里先挂一个"定时恢复"。
  - ★坑：PowerShell 5.1 的 `Set-Content -Encoding utf8` 会带 BOM，面板 `JSON.parse` 直接失败（台账会空）。JSON 一律用 node 写，或写完剥 BOM。
